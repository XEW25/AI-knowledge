- **两阶段框架**:
  - **Stage I** — 打分函数 `D_M(A_t, O_t; θ) → 标量`。**输入 = 最近 `T_O=2` 步观测 `O_t`(机器人状态 + 视觉特征)+ 策略生成的未来动作 `A_t`**;**刻意不用增长的历史轨迹**(避免在历史上过拟合)
  - **Stage II** — **conformal prediction** 构造**时变阈值**,给出误报率的统计保证

### 四类打分器(全部只用成功数据)
| 类 | 方法 | 思路 |
|---|---|---|
| **(a) 学出的数据密度** | logpO、**logpZO**⭐ | 连续归一化流(CNF)拟合成功轨迹观测分布 |
| **(b) 二阶分布** | NatPN(Dirichlet 先验,观测先 K-means 离散化)、DER(多元深度证据回归,`A_t\|O_t` 高斯 + Wishart 先验) | 分离 aleatoric / **epistemic** 不确定性 |
| **(c) 单类** | CFM、RND | 只见过正常数据,判是否属于该类 |
| **(d) Post-hoc(不学习)** | **SPARC**(动作平滑度,针对 OOD 常见抖动失败)、PCA-kmeans、**STAC** | 解析计算 |

### logpZO(本文新提出,表现最好)
- **logpO(已有)**:直接算 `log p(O_t)`,低似然=OOD。**问题**:需沿 ODE 轨迹**积分 `f_θ` 的散度**,高维难估
- **logpZO**:用同一 CNF,改评估**噪声估计 `Z_{O_t}` 的似然**——从 `O_t` 出发跑**前向 ODE** 在 [0,1] 积分 `f_θ` 得 `Z_{O_t}`;**`O_t` 分布内时 `Z_{O_t}` 近似标准高斯** ⇒ `p(Z)=C·exp(−0.5‖Z‖²)` ⇒ **分数本质 = ‖Z_{O_t}‖²**
- **优势**:完全绕开散度积分。**实测计算开销:0.04 s(Square)/ 0.033 s(Transport)每时间步**

### CP 用法(比标准 CP 更进一步)
- 构造**单侧、时变**的 CP band `C_α`:单侧(只关心分数偏高)、时变(各时刻正常水平不同)
- 从**成功 rollout 校准集**算每时刻 `μ_t` 与带宽 `h_t`;带宽取"**最大偏差**"的分位数(`max` 是为让 band 覆盖整条轨迹)
- **两种标定**:setting-dependent(各 ID/OOD 环境各自的成功轨迹)vs **ID-only**;仿真中 **ID-only 即可用于 ID 与 OOD 测试**,且**实践上更可取(无需采 OOD 数据)**
- **对比 STAC**:STAC 用**单一常数阈值**(累积散度的经验分位数);本文改进之一即**用时变 band 取代常数阈值**

## 实验设置
- **仿真**:Robomimic 的 **Square / Transport / Can / ToolHang**(略去 Lift——FM 与 DP 均 100%);OOD 由 **t=50 时模拟相机碰撞**制造(Can 用 t=15)
- **真机**:**双臂 Franka Emika Panda** —— **FoldRedTowel**(叠两次 + 推到桌角)、**CleanUpSpill**(一臂扶正倒杯、一臂持巾擦拭)。OOD:皱毛巾 + 蓝铲子干扰物 / 换成新绿毛巾;另有**人为扰动**(第一次折叠后拉扯毛巾)
- **策略 backbone 两种**:**FM(flow matching)** 与 **DP(diffusion policy)**
- **rollout 数**:仿真 **2000**,硬件仅 **50**;真实成功率 FM@FoldRedTowel ID = **0.96**,DP@CleanUpSpill ID = **0.82**
- 训练:仿真 1×RTX A6000 48GB;硬件 8×A100-80GB

## 结果(核实)
- **learned > post-hoc** 是总体结论;**logpZO 最一致**:combined accuracy **top-1 于 10/16** 情形(RND 5/16);硬件小样本下 **8/12 top-1、11/12 top-3**
- **learned 方法检测时间也最快**(除一例外,最佳检测时间总由 learned 方法取得)
- post-hoc 阵营:**STAC top-1 仅 3/16**,PCA-kmeans **从未最佳**;SPARC 最快(4/6)但**从未 top-1**
- 观察:**post-hoc 在 OOD 情形好于 ID**(猜测:成功 ID 轨迹与失败轨迹区分更明显)
- 可视化:learned 方法 **CP band 更紧、成功/失败分离更好**;post-hoc 因分离差**把大多数轨迹判为成功**
- 定性:Square 任务中**分数陡增恰好对应夹爪脱手的时刻**

## ⚠️ 与 Sentinel 说法的张力(重要)
> "Note we do not present STAC here as it was **slow to run on hardware in real-time**." —— 因为 **STAC 每步需生成 256 条动作预测**;论文另指出可少采几条但会**损害其统计性质**。
⇒ Sentinel 自称 STAC "negligible computational cost"(相对 VLM 成立),但**在真机实时约束下 FAIL-Detect 干脆没能跑它**。两者不直接矛盾,但对"STAC 可否放端侧"的判断有直接影响。
