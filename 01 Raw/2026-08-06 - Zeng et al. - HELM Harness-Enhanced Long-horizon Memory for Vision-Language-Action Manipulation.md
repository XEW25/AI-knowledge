**把上下文 H=8 → H=32(4×),TSR 仅 58.4% → 63.8%(+5.4 pp),尚余 17.7 pp 无法解释** ⇒ 问题不在窗口长度,在**执行环缺三样东西**

### 三个缺口(失败分类学)
1. **Memory gap (F_M)** —— 固定窗口丢弃**已完成子目标的证据**。原文例:*"At step t=47, the model cannot recall that the mug was placed in the cabinet at t=12; **it re-attempts the placement, corrupting task state**."*
2. **Verification gap (F_V)** —— 动作被反应式提出,**执行前无可行性检查**;不可行抓取、抓错物体、越工作空间的运动**静默执行并传播误差**
3. **Recovery gap (F_R)** —— 失败后模型**在被污染的状态上继续**,导致跨子目标级联失败

### 执行环(Algorithm 1)
每步:① EMM 检索记忆 `m_t` → ② `π_θ` 在 `(o_t, τ, g_t, m_t)` 下提出动作 → ③ SV 预测 `p_fail` → ④ HC **执行或触发恢复**

### EMM(Episodic Memory Module)
- key-value 存储:key = **CLIP ViT-B/32** embedding;value = (关键帧, 活动子目标, **完成状态**, 时间步, **紧凑状态 delta** = 夹爪位姿 + 深度得到的物体位置)
- **写入策略**: (a) 子目标完成 (b) 检测到失败 (c) **每 Δc=20 步一个 checkpoint**
- **检索**: cosine top-k,**k=3**;检索值**序列化成结构化文本,追加到 VLA 的语言输入**
- **压缩**: |M| > **N_max=50** 时,每个子目标只保留最近 checkpoint

### SV(State Verifier,核心学习贡献)
- 形式化目标:**`P(fail_t | o_t, a_t, g_t, M_t)`** —— **记忆条件化的执行前失败预测**
- 为什么必须条件化于记忆(原文):*"whether an action is valid often depends on **what has already been completed** (e.g., **placing an object that was already placed is a failure regardless of current visual feasibility**)"*
- **模型**: 3 层 **MLP [1024→512→256→1]**,ReLU + dropout 0.1。输入 `ô_t = [φ(o_t); k_top-1] ∈ R^1024`(当前观测 CLIP embedding **拼上检索到的 top-1 记忆 key**),再拼投影动作 `W_a a_t ∈ R^256` 与子目标文本 embedding `∈ R^256`
- **记忆是关键,不是容量**:去掉 `k_top-1`,**AUROC 0.847 → 0.791**;MLP 是**为低延迟刻意选的**(**12 ms/步**)
- **训练**: 从 VLA rollout 收 **50K** 三元组;**`y=1` 若 5 步内发生失败**;BCE + positive weight 4.0;Adam lr 1e-4,batch 256,**单卡 A100 ~2 小时**
- **阈值**: `p_fail ≤ θ_v = 0.65` 则执行,否则触发 HC 恢复

### HC(Harness Controller)——回滚怎么做
维护 **subgoal 栈 `S`**(初始由**提示 `π_θ` 自己分解任务**得到)+ **completion detector**(与 SV 同架构,训练在完成标签上)。

**触发**:`p_fail > θ_v` **或** completion detector 判负。**流程四步**:
1. 从 EMM **检索最近的 checkpoint / success 条目**
2. 发出**目标条件化的恢复序列**,prompt 为 **"return to the state shown"**
3. **把失败的 subgoal 重新压回栈**
4. 把失败条目追加进上下文

**最多 `R_max = 3` 次恢复尝试**,超出则判任务失败。

> ⚠️ **"回滚"不是仿真器 reset,而是拿一张历史关键帧当视觉目标、让 VLA 自己把世界开回去** —— 是**由策略执行的物理回归**。
> **HELM-Fwd 前向恢复变体**:对回滚不可行的环境,HC 改为**从当前受损状态生成前向恢复计划**;两个变体都做了评测。

## 结果
- **LIBERO-LONG: OpenVLA 58.4% → 81.5%,+23.1 pp**
- 长上下文 H=32 对照:仅 63.8%(+5.4 pp)
- **SV vs 替代**:rule-based verifier **+6.8 pp**;**SV +8.4 pp**;ensemble uncertainty +9.5 pp 但**需 5× 推理成本**
- **SV 去掉记忆上下文退化 6.1 pp**(EMM–SV 耦合)
- **失败模式计数**:三类都降,**F_R 降幅最大(82%),由 rollback 驱动**
- 评测:**LIBERO-LONG**(500 eval episodes)、**CALVIN ABC→D**(平均完成链,上限 5)、**LIBERO-Recovery**(本文发布的**扰动注入**失败恢复评测协议)
- **9 个 baseline**:含 oracle memory、long-context、rule verifier、ensemble、**same-budget LoRA**、forward-recovery 变体
