# Real-robot eval bench — 任务集设计与搭建清单

> **团队专属、有时效的可执行清单**。把 [[Real-robot evaluation]] 的框架落到具体机械臂平台上：跑哪些任务、买什么、难度怎么调、每条 roadmap 挂哪些任务。
> 制定于 **2026-08-06**。**换本体、换模型基座或改 roadmap 后需重审**。

## 适用假设（变了就作废）

| 项 | 当前假设 |
|---|---|
| 本体 | 桌面机械臂，**单臂 + 双臂**两种配置 |
| 模型 | 采真机数据 → **微调 π0** → 真机评测 |
| 已有任务 | 抓瓶子（单臂）· 双臂交接果汁盒 · 叠 2 个碗 |
| 已有资产 | 瓶子、碗、果汁盒 |
| 计划中 | 采购抽屉，夹爪拉开 + 合上 |
| 后续 roadmap | ① 推理优化（量化/加速） ② 具身架构设计 ③ 仿真训练优化 |

**⚠️ 核实状态**：外部 benchmark 引用（RoboDojo / ATOM-Bench / RoboLab / PhAIL）均来自 WebFetch 摘要器，**未对照原文核实**。任务设计与判据是本库自有综合。

## 1. 现状诊断

运动轴定义见 [[Real-robot evaluation]]。当前覆盖：

| # | 运动轴 | 现状 |
|---|---|---|
| 1 | 抓取-放置 | ✅ 抓瓶子 |
| 2 | 精密对位 / 插入 | ⚠️ 叠 2 碗——**容差太松，测不出精度退化** |
| 3 | 非抓握操作 | ❌ |
| 4 | 接触丰富 / 力调制 | ❌ |
| 5 | 铰接物体 | ⏳ 抽屉已在计划中 |
| 6 | 可变形物体 | ❌ |
| 7 | 双臂-顺序（交接） | ✅ 果汁盒（arm1 抓取→置于中转位→arm2 抓取→放至目标，4 阶段） |
| 8 | 双臂-同步（闭链） | ❌ **最大空白** |

**8 条轴覆盖 2.5 条。** 两个关键结论：

- **轴 8 是最大浪费**：交接任务本质是「两个单臂任务接力」，可完全顺序执行。真正的双臂协同是**闭链**的（两臂间有力耦合，一臂动会改变另一臂负载）。**买了双臂硬件，一半的双臂能力从未被测过。**
- **轴 3 成本近乎为零**：用现有瓶子倒下来扶正即可，却是 RoboDojo 明确列入的一轴（`stand_up_bottles`）。

指令轴 / 结构轴 / 泛化轴 / 扰动轴：**全部为空**。

## 2. Tier 0 — 回归底座（任何优化都跑）

| 任务 | 覆盖轴 | 新增成本 | 复位成本 | 建议打分量 |
|---|---|---|---|---|
| 抓瓶子（+ 泛化条件组） | 1 | 零，保留 | 中 | time-to-success CDF |
| **叠 3–4 个碗**（从 2 个升级） | 2 精密 + **误差累积** | 两个碗 | 中 | 每层完成数 + 完成时间 |
| 双臂交接果汁盒 | 7 双臂顺序 | 零，保留 | 中 | 分阶段 progress + 完成时间 |
| **扶正倒下的瓶子** | 3 非抓握 | **零** | **低（近自复位）** | 位姿角度偏差 + 完成时间 |
| **抽屉开合** | 5 铰接 / 约束流形 | 一个抽屉 | **零（自复位）** | **位移 cm** + 残余缝隙 mm |

**五个任务覆盖五条轴，只需买两个碗和一个抽屉。**

**叠碗必须从 2 升到 3–4**：2 个碗对位容差太松；层数一多，**误差累积**才会显现——这正是量化评测最需要的结构（见 [[Xu et al. - QVLA Not All Channels Are Equal in Vision-Language-Action Models Quantization|QVLA]] 指出的 VLA 量化特征失败模式）。

## 3. Tier 1 — 补关键空白（按优先级）

| 优先级 | 任务 | 覆盖轴 | 说明 |
|---|---|---|---|
| **P0** | **一臂拉住抽屉保持开启 + 一臂取物** | 8 双臂同步闭链 | 复用抽屉资产；抽屉不会跑，比扶瓶子稳定，是**最容易搭的同步任务** |
| P1 | 开抽屉 → 取瓶 → 关抽屉 | 5 + 1，3 阶段 | 抽屉任务的自然 v1 |
| P2 | 抹布擦拭指定区域 | 4 力调制 | 纯位控 policy 会以特有方式失败（悬空擦 / 压太狠触发保护），判别力强 |
| P3 | 把瓶子装进布袋 / 折一次毛巾 | 6 可变形 | 高复位成本，低 n；且仿真侧最难对齐，可最后做 |

**若只做一个双臂同步任务，选 P0，不要选拧瓶盖。**

## 4. 结构轴 — 串联即可，不需新资产

- **长程 + 组合泛化**：`开抽屉 → 取瓶 → 扶正 → 放进筐 → 关抽屉`（5 阶段）。原子都单独训过、这个组合没训过 → 白送一个 ATOM-Bench 式的组合泛化测试（CFS）。
- **记忆**：放置后用布盖住，后续步骤需知道底下是什么（抄 RoboDojo `cover_blocks`）。一块布的成本。
- **扰动恢复**：任意任务执行中途人手移开目标物 10cm。**不占任务位、零资产、每次多两秒**，直击开环 chunk 预测的软肋。

## 5. 指令轴 — 全部做成条件，不占任务位

挂在「抓瓶子」和「扶正瓶子」上，只改摆放和 prompt：

- **视觉 grounding**：三个不同颜色/大小的瓶子，指定拿哪个
- **空间关系**：「把瓶子放到碗的**左边**」
- **计数 / 逻辑**：「把**所有**倒下的瓶子扶正」「拿红瓶**或**蓝瓶」
- **措辞三档**：模糊 / 默认 / 详细 —— RoboLab 报告「模糊必挂、过详细也退化」，值得在自家 π0 微调模型上复现一遍

## 6. 泛化轴 — 条件

未见实例 / 未见位置 / 干扰物 0→5 个 / 光照 / 背景。挂 Tier 0。

## 7. 抽屉任务专章

已在采购计划中，值得单独展开——它有一个被低估的优势。

### 为什么优先级应该更高：它自己是自己的复位机构

`open → close` 天然回到初始状态，**可无人值守连续跑**。同样人力预算下能给到 **10× 以上的 rollout 数**。

> 前面「n 太小、CI ±30pp、什么都测不出」的死结，在这个任务上直接解开。**其他任务只能 n≈30，抽屉可以 n=300+。**

**定位：不只是补一条能力轴，而是唯一的高精度回归探针。** 推理优化那条线尤其依赖它——量化前后的差异需要大 n 才测得出。

### 采购要点

**第一旋钮是把手类型，不是抽屉本身。** 建议买**可换把手**的，或买横杆把手 + 自己 3D 打印凹槽面板贴上去。

| 旋钮 | 易 → 难 |
|---|---|
| **把手类型** | 横杆 → 拉环 → 凹槽式（需插指） → 无把手推拉 |
| **滑轨阻尼** | 顺滑 → 有阻尼/略卡（**这一档开始需要力调制，顺带吃到轴 4**） |
| 抽屉朝向 | 正对 → 斜置 → 位置随机 |
| 目标状态 | 全开 → **开到指定程度**（连续量控制，难度陡增） |
| 抽屉内容 | 空 → 放物体（拉开时会滑动，增加动态） |

### 「合上」是一个设计选择

| 实现 | 测的轴 |
|---|---|
| 抓住把手往回推 | 5（继续约束流形） |
| 夹爪闭合当推杆推 | **3 非抓握** |

**不在指令里指定 → 变成 affordance 选择测试**，看模型有没有泛化出「推也行」。π0 微调后大概率模仿演示做法，这本身就是有信息量的观测。

### 升级路径（同一套资产吃到轴 8）

- **v0** 拉开 + 合上 → 轴 5，自复位，大 n 探针
- **v1** 开 → 取瓶 → 合 → 轴 5 + 1，3 阶段
- **v2** 开 → 取瓶 → 扶正 → 放筐 → 合 → **5 阶段长程 + 组合泛化**
- **v3** 一臂拉住保持开启 + 一臂取物 → **轴 8 双臂同步闭链**

### 打分：白送的连续量

抽屉位移（cm）是**天然连续 progress 变量，没有代理缺口**——位移就是任务本身。

- 开：位移达阈值记成功；**整条位移-时间曲线**记为连续指标
- 合：残余缝隙 mm
- 可自动测量（滑轨贴标记 + 固定机位，或深度相机）

### 三个必踩的坑

1. **柜体必须固定死。** 柜体一滑，测的就是「推柜子」；且每轮后位置漂移，**初始状态可复现性崩掉 → 所有配对统计作废**。用夹具或配重固定，每轮评测前核对位置。
2. **力矩保护是隐藏变量。** 碰撞检测触发停机，在数据里长得像「任务失败」，但原因是控制器保护不是 policy 错。**必须单列为一类失败**，否则会把「量化让动作更抖 → 触发保护」误读成「量化让模型不会开抽屉了」。
3. **硬件会漂移。** 滑轨跑几千次后阻尼变化——这正是自复位任务大 n 的代价。**定期用脚本轨迹或人类遥操重测基线**，否则三个月后会把「抽屉变紧」误判成「模型退化」。

## 8. 按 roadmap 挂载

| 场景 | 跑什么 | **不**跑什么 |
|---|---|---|
| **推理优化**（量化/加速） | Tier 0 全部 + 5 阶段长程串联 + 扰动条件；抽屉当大 n 探针；重点看误差累积与轨迹质量 | 指令轴（量化基本不动语义能力，纯浪费物理时间） |
| **架构设计**（分层/记忆/双系统） | 长程串联 + 记忆条件 + 双臂同步(P0) + 扰动恢复 | 单步抓取（对架构改动**零信息**） |
| **仿真训练优化** | 只跑刚体的 1/2/3/5/7，先建 sim-real 秩相关基线 | 可变形(6)、力调制(4)——sim 对不齐，相关性一崩后面全废 |

指标选择见 [[Real-robot evaluation]] 的「指标分层」：验收用成功率非劣性检验，筛选用配对连续量，诊断用 SPARC/jerk（**只在成功 rollout 上算**）。

## 9. 立即可做（按性价比）

1. **建 human baseline** — 人类遥操跑现有三任务各 20 次，记成功率与耗时。半天成本。判断任务是否已饱和的**唯一客观尺子**；顺带给 PhAIL 式 Human-Relative Throughput 打底。
2. **难度校准到基线模型 40–70%** — 用旋钮调（叠碗 2→5、干扰物 0→5、位置固定→随机 20cm、指令详细→模糊）。**校准完成前不要开始正式评测**，否则前面所有统计设计白费。
3. **固定初始布局** — 每任务定 N 个预设 layout，用「回放预采集布局 + 半透明叠加对齐」（RoboDojo 做法，一个相机 overlay 就能做）。
4. **打分改双盲** — 录像 + 至少两人独立事后打分，判分者不知道跑的是哪个模型。**不花物理时间，纯赚。**
5. **零成本加两个 condition** — 扶正瓶子（轴 3）+ 扰动恢复。当天就能跑。

## 10. 待决问题

- 单次评测的物理时间预算是多少？这决定 `任务数 × 条件数 × trial 数` 怎么分配，也决定抽屉探针能跑到多大 n。
- 是否需要与外部可比？若需要，Tier 0 里 `stack_bowls` / `stand_up_bottles` 与 RoboDojo Piper 分支同名，**协议对齐后可做粗略对照**（本体不同仍不严格可比）。
- 子问题 2（初始状态可复现性）与子问题 3（打分细则）尚未展开——上面所有配对统计都建立在其上。
